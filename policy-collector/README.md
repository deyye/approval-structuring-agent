# 投资项目政策文件采集器

对应任务书：**问题解决类（二）研究利用大模型定期采集投资项目政策文件并落地数据库**
业务指导：省经济信息中心电子政务部

---

## 一、它做什么

按任务书口径，对政府官方网站政策专栏做**智能采集**，自动研判文件是否属于**投资项目类政策**，
并按四类标准化归集，落地为可查询的数据库。

| 任务要求 | 实现位置 |
|---|---|
| 采集范围：中央人民政府、国家发改委、浙江省发改委、各省级发改委政策专栏 | `collector/sources.py`（33 个源，ID 唯一） |
| 提取：标题、正文、发布日期、文号、政策分类、附件 | `collector/extract.py` |
| 自动研判是否属于投资项目类政策 | `collector/classify.py` → `is_investment` |
| 标准化四类归集 | `collector/classify.py` → `category` |
| 数据去重 | `collector/store.py` → 四键去重 |
| 落地数据库 | `out/policies.db`（SQLite） |
| **定期采集** | `run.py --since YYYY-MM-DD` 增量模式 |

## 二、四类分类口径（严格按任务书原文，未自行发挥）

| 类别 | 解决的问题 | 覆盖范围 |
|---|---|---|
| **引导类** | 往哪投 | 发展规划、产业导向目录、区域布局指引 |
| **准入类** | 让不让投 | 审批/核准/备案管理制度、市场准入负面清单、能耗、环评等前置准入门槛 |
| **保障类** | 靠什么投 | 土地、资金、信贷、能耗、人才等要素供给及倾斜支持政策 |
| **激励约束类** | 投了怎样 | 财政奖补、税收优惠、价格支持等正向激励；项目全过程监管、绩效评价、后评价、责任追究等约束要求 |

分类是**可解释的加权规则**：每个判断都留下命中的关键词，写入 `category_reason`，
并给出 `category_confidence`。得分与第二名接近时（<0.6）会在依据里提示"建议复核"。

大模型不是必需——标题里通常就写着类别，规则先判掉绝大多数；
真正拿不准的再走 `classify.llm_review_hook()`（已留接口，当前环境无模型凭据故未启用）。

## 三、去重策略（四键逐级收紧）

| 优先级 | 键 | 解决的场景 |
|---|---|---|
| 1 | `url` | 同一网址重复抓取（分页重叠、重跑） |
| 2 | `doc_number` | **同一份文件被多站转载**（部委原文 + 省政府转发）——最常见 |
| 3 | `content_hash` | 换了网址、改了栏目的同一文件（正文前 3000 字 + 归一化标题取指纹） |
| 4 | `title_key` | 标题归一化后同名，兜住正文抓取失败的漏网 |

为什么不止用指纹：转载版本的 url、栏目、附件往往全变，但**文号是文件的身份证**，
所以 `doc_number` 优先级高于正文指纹；没有文号的（规划、目录类）才退到指纹。

## 四、用法

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt

# 全量采集（首次）
.venv/bin/python run.py --max-pages 6 --detail-limit 800

# 定期增量采集（建议每周执行，只收这个日期之后的）
.venv/bin/python run.py --since 2026-09-01 --max-pages 4

# 只看某个源 / 快速探查（源 ID 唯一，可按省选）
.venv/bin/python run.py --sources gov_cn ndrc --max-pages 3
.venv/bin/python run.py --sources prov_hebei prov_henan --max-pages 6
.venv/bin/python run.py --list-only          # 只抓列表，不抓正文，很快

# 调整研判门槛后重判全库（不联网、不碰对方站点）
.venv/bin/python run.py --reclassify --profile strict   # 或 broad

# 看库内统计、按地区覆盖、以及哪些源没抓到、为什么
.venv/bin/python run.py --report

# 导出含非投资项目类（默认只导投资项目类）
.venv/bin/python run.py --all

# 排查"是代理还是站点"：绕过环境变量里的代理直连对照
.venv/bin/python run.py --sources prov_jiangxi --list-only --no-proxy

# 维护脚本（都是幂等的，只填空、不覆盖已有值）
.venv/bin/python scripts/repair_doc_numbers.py     # 回填「令号/公告号」形态的文号
.venv/bin/python scripts/repair_source_ids.py      # 历史 source_id 迁移到唯一 ID
.venv/bin/python scripts/prune_noise.py --dry-run  # 查噪声（**先看清单，确认后再执行**）

# 删除数据只走这个工具（带数量护栏 + 自动备份 + 必须显式确认）
.venv/bin/python scripts/safe_delete.py --where "条件"              # 只数不删
.venv/bin/python scripts/safe_delete.py --where "条件" --max 10 --yes  # 超过 10 条即拒绝
```

**删数据的三条铁律**（前两条是本项目踩过事故换来的）：

1. **不要写临时 SQL 直接 DELETE**，一律用 `scripts/safe_delete.py`：
   它先只数、打印样本，`--max` 超限直接拒绝（专治通配符写宽），删除前把整行
   备份到 `out/deleted/*.json`，且必须显式 `--yes`。
2. **通配符要盯住作用域**：`url LIKE '%gov.cn%'` 想删 2 条，实际匹配**所有** `.gov.cn`
   域名——一次删掉 1102 条省级记录。用通配符时先跑一遍"只数不删"，看清数量。
3. **删完立刻用 `--report` 核对总数**，与删除前的数对上再继续别的工作。

⚠️ `--list-only` 只抓列表、不抓正文，记录会**照常入库但没有正文**。
下次全量运行会自动补全（见"已知坑"第 14 条），不需要手工处理。

产物：

| 文件 | 说明 |
|---|---|
| `out/policies.db` | SQLite 主库（可被其他系统直接查询） |
| `out/policies.xlsx` | 人工查阅版（分类着色 + 附带统计页） |
| `out/coverage.json` | 各源覆盖情况，**含失败原因**——直连不了的源不会被静默跳过 |

## 五、分类门槛是一个业务边界，做成了档位

第一版跑完抽查发现 **55 条里 47 条（85%）** 被判为"投资项目类"——「特殊教育发展规划」
「森林年采伐限额复函」「出境入境管理规定」全进来了。四类归集因此失去意义。

根因：`项目/工程/建设` 这类词在**任意一篇长条例的正文里必然出现**，所以判据**一律限定在标题**——
政策主旨写在标题上。逐步校准：

| 版本 | 判据范围 | 判为投资类 |
|---|---|---|
| 初版 | 强信号不限位置 + 弱信号≥2 | 85% |
| 二版 | 强信号不限位置 + 核心词在正文 | 73% |
| 三版 | 核心词在正文、需≥2 | 24% |
| **现行（strict）** | **强信号与核心词均只看标题** | 见 `--report` |

但任务书对「引导类」的定义里**明写了"发展规划"**，而国家级/省级规划文件极多，
放宽会把「国民健康规划」「全民健身计划」一并收进来。**这是业务边界，不是技术问题**，
所以做成两档，默认取高精度的 `strict`：

- `strict`（默认）：只收标题即指向投资/项目的文件，精度优先
- `broad`：把"发展规划/方案/纲要/行动计划"类也算进来，召回优先

调档位后用 `--reclassify` 本地重判即可，**不需要重新抓网页、不给对方站点添麻烦**。

## 六、实测覆盖情况（2026-09-11）

**能直连（本机能自动跑）**：中央人民政府政策文件库（官方 JSON 接口，6200+ 条可翻，最稳）、
国家发改委政策发布 5 个子栏 + 委内动态，以及 **19 个省级发改委**（北京、天津、河北、山西、辽宁、
吉林、上海、江苏、福建、河南、湖南、广东、广西、海南、重庆、四川、贵州、陕西、宁夏）。

**需要浏览器渲染层（列表由 JS 注入，静态抓不到）**：

| 源 | 依据 |
|---|---|
| 浙江省发改委 | 栏目页正文仅 4 字符，无日期；聚宝 CMS，`dataproxy.jsp` 已下线 |
| 江西省发改委 | **网络已通**（见下"TLS 兼容"），但首页是 JS 模板（`{{pcUrl}}` 占位符），30 个栏目页正文 18–140KB 全是 JS 骨架，解析均 0 条 |
| 安徽省 / 山东省 / 新疆 | 首页可达但未发现政策栏目（正文仅 2–4KB，JS 骨架） |
| 内蒙古自治区 | 栏目页正文仅 782 字符，无日期 |

**反爬拦截（HTTP 412，需 Cookie 或浏览器指纹）**：湖北省、甘肃省。
实测加 `Referer`、加 `Cookie` 均无效，属 WAF 层面拦截。

**网络/TLS 层不可达**：

| 源 | 真实成因 | 可否修 |
|---|---|---|
| 江西省（已修） | `UNSAFE_LEGACY_RENEGOTIATION_DISABLED` —— 站点要求旧式服务器连接，OpenSSL 3 默认关闭 | ✅ **已修**：`SSL_OP_LEGACY_SERVER_CONNECT`，修后 HTTP 200 / 235KB |
| 黑龙江、青海 | `SSL: UNEXPECTED_EOF_WHILE_READING` —— 握手后被服务端断开；试过 legacy connect、降 SECLEVEL、放宽 TLS 版本均不通 | ❓ 需进一步排查（可能要求特定 TLS 扩展、SNI 策略或 IP 白名单） |
| 云南省 | **DNS 解析失败**（`ynfgw.yn.gov.cn` 本机无法解析），不是站点问题 | ❓ 需换 DNS 或确认域名 |

**这不是"全部搞定"，是"边界清楚"**：能直连的 22 个源可按周期自动跑；
不能直连的已逐条给出**可复现的依据**与成因分类，而不是笼统写成"失败"或假装它们不存在。

⚠️ 特别说明：**"0 条"至少有三种完全不同的原因**——JS 注入、解析规则缺口、站点确实没发新政策。
把它们混为一谈会把工期估错（前两个要改代码，第三个什么都不用做）。所以覆盖报告里
`js_required` / `parser_gap` / `failed` 是三档独立的 `status`。

## 七、已知坑（都已在代码里修掉，留作记录）

1. **中国政府网用 `<h2>` 放「索 引 号：」这类版式标签** —— 标题提取若把 `h2` 排在
   `<title>` 前面，全库标题会变成「索 引 号：」。故顺序为 og:title → h1 → title → h2。
2. **正文不能靠正则切嵌套 `<div>`** —— 非贪婪正则在第一个 `</div>` 就截断，抽出来的
   正文以站点头部导航开头。改用 `HTMLParser` 维护标签栈后正常。
3. **列表页同样不能靠正则切嵌套 `<div>`** —— 这是最贵的一个坑。原先"先切块、再在块里找链接"，
   同样因嵌套在第一个 `</div>` 截断：河北某栏目页明明有 16 个详情链接却解析出 **0 条**，
   河南 20 个链接出 **1 条**。两个省因此在上一轮被误记为"低产"，看着像反爬，
   实际是解析规则把数据切碎了。改为**以 `<a>` 为中心 + 日期就近窗口**后，
   同一批省从不到 20 条升到 246 条。
4. **地址不一定写在 `href` 里** —— 天津某 CMS 用
   `onclick="isDownLoad(this,'https://…/t20260910_7371699.html')"` 承载跳转，页面上**没有**
   href 属性。只认 href 的解析方式会把这整页判成"0 条"，进而**误判为 JS 渲染**。
   现取地址时先找 href，找不到再看属性里有没有 http(s) 文章地址。
5. **日期不一定在链接外面** —— 同一站把 `<span>标题</span><span>日期</span>` 一起放进 `<a>`，
   日期在链接**内部**。日期查找顺序改为：`<a>` 文本 → 本条之后到下一条之前 → 本条之前 120 字符。
6. **源 ID 从域名首段推断会大面积撞车** —— `fgw.beijing.gov.cn`、`fgw.shanxi.gov.cn`、
   `fgw.ln.gov.cn`… 全算成 `prov_fgw`，一个 ID 覆盖 10 个省：`--sources` 选不中单个省、
   覆盖报告互相覆盖、库内无法按省统计。已改为显式维护省份码，并提供
   `scripts/repair_source_ids.py` 按 region 回填历史数据（幂等）。
7. **抓取返回 0 条必须报错，不能默默返回空列表** —— 浙江省曾因此被标成「✓ 新增 0」：
   看着跑完了，实际一条没抓到，日志里也没有异常。这类"沉默的 0 条"会被当成
   "该站最近没发政策"，漏洞直接进交付物。现在按成因分三档报错：
   `js_required`（JS 注入，需渲染层）/ `parser_gap`（**我们有内容没解析出来，是代码缺陷**）/
   `failed`（网络、证书、反爬）。`parser_gap` 这一档尤其重要——它和 `js_required` 都是 0 条，
   但一个是"要加渲染层"、一个是"改几行正则"，混在一起会把工期估错。
8. **文号会被前文"粘住"** —— 正文里标题重复一遍，导致抽出
   「治理有关工作的通知国办发〔2026〕24号」。加了「剥掉正文开头重复标题」+ 机关代字
   长度/虚词校验后干净。
9. **列表里的嵌套条目** —— 国家发改委每条通知的 `<li>` 内嵌了「相关解读」的 `<li>`，
   通用解析会把「答记者问」当成政策原文。已改为按正文路径严格匹配。
10. **不要在入库时按"是否投资项目类"硬过滤** —— 门槛以后可能要调，一旦删掉就补不回来。
    现在全量入库、打标记，导出时再过滤。
11. **跨站链接一律不收** —— 省级栏目的「国家政策法规」栏会转载中央文件，收进来归属会错记成
    该省（`region` 字段失真），而中央文件已由国家级源覆盖。
12. **"以 index 结尾 = 栏目页"是错的，要看父目录** —— ⚠️ 这条是**清理脚本自己出错**的教训：
    为了清掉陕西的政府信息公开目录页（`/zfxxgk/zfxxgkzd/index1.html`），我加了"index 结尾即栏目页"的
    判据，结果**一次误删了 59 条**——因为辽宁等站的文章地址形如
    `/fgw/zc/zcjd/2026082815040164859/index.shtml`，文章 ID 是**目录名**、文件恰好叫 `index.shtml`。
    正确判据是**看父目录里有没有长数字串**：有（≥6 位连续数字）就是文章 ID，没有才是栏目落地页。
    教训有两层：一是"删数据"的规则必须先在**正反两个方向**上都验一遍（既确认真阳性，
    也确认不会误伤），二是清理脚本要带 `--dry-run` 且**执行前先逐条看清单**。
13. **翻页：读链接不够，还要能"探测"模板** —— 这条是**后果最严重的一个坑**。
    两层问题：
    - 各站翻页写法差异极大：辽宁用 `/fgw/zc/zcjd/8375b354-2.shtml`（UUID + 序号）、
      TRS 用 `index_2.shtml`、还有站用 `?page=2`。按 `index_N.shtml` 猜，辽宁每个栏目
      只拿到第 1 页的 15 条（该栏目实际共 7 页）。已改为**优先从页面自身读「下一页」链接**
      （`next_page_url`：依次看 `tagname` 属性 → `href` → 属性里的相对路径）。
    - **但很多 CMS 的翻页链接是 `document.write` 在浏览器运行时拼出来的，静态 HTML 里
      根本没有 `<a href>`** —— 读链接这一招直接失效。实测北京市发改委某栏目 JS 写着
      `countPage = 134`（共 **134** 页），规则是 `index.htm → index_1.htm → index_2.htm`
      （`.htm` 而非 `.html`），而按文件名猜的 `index_1.html` 一律 404。
      **结果是每个栏目只抓到第 1 页的 15 条，数据"看着有条目"，实际少了两个数量级。**
      现增加 `detect_page_template()`：逐个试候选模板，取「能抓到 + 解析出条目 +
      与第 1 页内容不同」的第一个（`PAGE_TEMPLATES` 覆盖 `index_N.htm/.html/.shtml`、
      `indexN.*`、`?page=N`、`index.jsp?pageNo=N`）。北京实测探测到 `index_%d.htm`、
      重庆探测到 `?page=%d`，第 2 页与第 1 页零重叠。
      探测不到时**只取第 1 页并打印一行明确日志**，不假装抓全。
    - **翻页地址当 `urljoin` 基准时必须剥掉 query**（这一条是修上面两层时自己引入又修掉的
      回归，留作记录）：`?page=2` 型翻页若把 base 拼成 `.../zfxxgk?page=2`，
      `urljoin` 会把 `zfxxgk` 当成**文件名**、父目录当成 `/`，该页所有相对链接被解析成
      `https://host/fdzdgknr/...`（少了 `/zfxxgk`）→ 整页 404。
      实测陕西省政府网因此**第 2 页起 25 条详情全部抓取失败**，而第 1 页正常——
      症状很像"对方站点不稳定"，实际是自己的地址拼错了。
      两处修：`apply_page_template` 对 query 型模板**保留目录末尾斜杠**；
      `parse_list_generic` 内部**统一剥掉 base 的 query/fragment** 再解析。
14. **`--list-only` 入库的空壳记录会挡住后续详情抓取** —— 该模式只抓列表、不抓正文，
    却照样入库。之后跑全量时这些 URL 已在库中 → 被当成"已采集"跳过 → **正文永远补不上**，
    库看着有几千条、实际没有内容可读。现两处修正：跳过集合只统计"已有正文"的记录；
    命中重复但原记录无正文时，用新抓到的详情 `enrich()` 补全而不是跳过。
15. **`--sources` 的逗号写法** —— `argparse` 的 `nargs='*'` 只认空格分隔，
    写 `--sources a,b` 时整串被当成一个（不存在的）源名，匹配不到源后直接退出：
    看着像跑完了，实际一个源都没采。现已在 `parse_args()` 后按 `[,，]` 拆分，
    两种写法都支持。
