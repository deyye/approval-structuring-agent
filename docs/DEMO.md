# 工作流程演示（约5分钟）

安装 README 中的依赖后运行：

```bash
python scripts/demo.py --review-demo --data /tmp/approval-workflow-demo --serve
```

打开终端打印的本地地址（默认 http://127.0.0.1:8765）。生成并实际解析7份虚构PDF：两个项目各三阶段，加一份故意包含冲突、阶段待确认的材料。重复运行按文件内容去重；建议用独立演示目录。

## 演示顺序

1. **看进度**：顶部是7份文件、3个项目及待核对项数；左侧标明建议书、可研、初设分别有几份。未上传不等于必须补齐，取决于实际任务范围。
2. **核对普通项目**：点击“开始 / 继续核对”，在原文证据旁“确认无误并下一项”。需要改动才点“修改”，保存后继续下一项。
3. **区分差异**：基本信息/建设指标分别查看，筛选“内容变化”“待核对”“仅表述差异”。变化不自动认定为异常。
4. **核对冲突项目**：选“演示待核对项目”，先按演示口径把阶段确认为初步设计。100和200平方米故意矛盾，不可直接一键确认。进入“修改”，可将一条改为相同数值以演示纠错，或在有原文依据时修改指标名称/统计范围；改完后观察其余待办仍然保留。真实材料不能靠改名掩盖冲突。
5. **导出范围**：点击“导出当前项目”，Excel只含当前项目；“更多导出”可导出全部项目Excel或当前项目JSON。待核对项和原文证据随Excel保留。
6. **看设置**：模型配置及连接测试位于侧栏折叠区；处理详情默认折叠。

“待核对项已处理”仅说明当前待办清零，不代表全部字段人工验收、阶段材料齐全或项目无异常。最近批次处理进度在服务重启后不保留，已入库文件及核对状态持久保留。

## 普通六文件回归演示

```bash
python scripts/demo.py --data /tmp/approval-six --serve
```

真实PDF可使用 `--samples /private/path`，不要与 `--review-demo` 一起使用。所有公开演示内容都是虚构材料。
