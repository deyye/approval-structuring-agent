## 用户现在怎么操作

1. 上传批复。顶部四步说明当前主流程，最近批次展示每份文件正在做什么。逐文件完成数量用于显示批次进度，不表示单份文档计算进度。
2. 处理结束后点击“开始 / 继续核对”。按原文确认、修改或处理指标名称对齐。
3. 待办清零后查看阶段差异和材料覆盖情况，再导出当前项目。待办清零不代表审批材料齐全，也不代表项目通过审批。
4. 文件失败时展开最近批次，按原因修复后重新选择文件；网络连接中断时先重新连接进度。服务重启后已保存的文档和人工修订保留，未完成文件需重新提交。

任务日志只保留最近的有限批次，保存在数据目录 jobs/state.json 中，不保存上传字节或模型密钥；它不参与文档列表、比对或导出。模型阶段仅在启用时发生，未配置 API 时使用现有本地解析方案。没有自动重传材料或自动重试整个批次。

## 验证与边界

新增 5 项任务状态回归；扩展 DOM/真实 HTTP 交互回归，覆盖当前文件筛选、重复上传和结果跳转。Docker 验收脚本增加任务记录重建持久性验证。浏览器预览环境启动受依赖缺失影响，本轮未获得有效的视觉截图验收；DOM 测试不冒充视觉验收。

这是本机单用户工作台。大批量长期存储仍需分页与索引库，多人共用仍需账号权限和任务调度；本次未将其改成百万级生产平台。尚未接入实际供应商凭据，不能据此声明外部模型的抽取效果。
